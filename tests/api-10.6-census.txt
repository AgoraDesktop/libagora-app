# The third census in this suite, and the one that measures the OTHER direction. `refusal_census.txt` holds what the
# implementation says it cannot do; `owed_census.txt` holds what the headers say they do not do yet; both are claims
# written in this tree's own voice. THIS ONE IS THE MEASUREMENT THOSE CLAIMS ARE ABOUT — the fraction of Apple's
# 10.6 AppKit surface that a caller can actually reach — and it exists because that number was, until now, produced
# by hand and never the same twice: three separate counts of "what is missing in libagora-app" gave 4%, 44% and 54%,
# each measuring a different thing (progress on the 10.11 gap list, header filenames, `@implementation` blocks).
# A number nobody can recompute is not a measurement.
#
# **THE REFERENCE IS 10.6 RATHER THAN 10.11, AND THAT IS THE TREE'S OWN CHOICE RATHER THAN A CONCESSION.**
# `COCOA-10.11-SURFACE-PLAN.md` §2.1 records it: "The tree's own reference today is 10.6 … `libagora-app`'s era pins
# are 10.2/10.5/10.6. The 10.11 SDK is therefore a NEW reference, not a replacement." Measuring against 10.11 charges
# this tier for 47 classes that only exist in 10.7–10.11 and that no slice has promised yet; measuring against 10.6
# asks the question the tree is actually answering. The plan's own §0 verdict is the same finding this census
# produces: the gap is not the 10.7–10.11 delta, it is the 10.6 surface this tree never finished.
#
# **THE SDK IS NOT IN THIS REPOSITORY AND MUST NOT BE.** Apple's headers are not redistributable. What the plan
# commits, and what is committed here, is the RECIPE plus the generated NAME MANIFEST: `tools/api-ledger manifest`
# reads an SDK checkout and emits facts — class names, superclasses, protocol names, selector names, function
# names — and `api/10.6/appkit-manifest.txt` holds them. No declaration, comment, annotation or line of Apple's
# expression is copied; a manifest of names is the same kind of fact as a symbol table, which is why it can be
# committed at all. Regenerating it needs the SDK and is documented in `api/10.6/README.md`.
#
# **INHERITANCE IS RESOLVED, WHICH IS WHAT MAKES THIS A MEASUREMENT RATHER THAN A DIFF.** The plan requires it in as
# many words (§2.4: the probe must answer for inherited methods, because that is what `respondsToSelector:` does). So
# an Apple selector counts as present when this tree declares it on the class, inherits it from a local superclass, or
# implements it in a `.m` body anywhere along that chain — and `@property` is expanded to getter and setter, because
# an accessor is a door a caller sends. Without this the ledger reported `NSTextView 0 of 130` for a class that
# inherits most of its surface from `NSText`, which is the single most instructive false negative this instrument has
# produced.
#
# **AND THE COMMENT LINES IN THIS BLOCK ARE PROSE, WHICH IS TO SAY THEY CAN GO STALE.** The metrics below are pinned
# and the gate fails if one moves; the four lines above are hand-written summaries of them, and this file carried
# "80 declared" for three slices after the number became 86 — the gate did not notice, because a comment is not a
# metric. Recompute them when you re-pin, from `api-ledger census`, rather than editing the numbers by eye.
#
# **A FUNCTION COUNTS WHEN IT IS A SYMBOL, NOT WHEN A HEADER MENTIONS IT.** `functions-present` is answered by
# `nm -D --defined-only` on the built library, which is the question a caller's link line asks; `functions-declared`
# is the header count kept beside it, and the two disagreement counts are pinned at zero because neither is drift.
# `NSEventMaskFromType` is exempt from being a symbol because Apple's `NS_INLINE` makes it a bodied door.
#
# **THE FORMAT IS `name count`, one per line, and it is compared in BOTH DIRECTIONS** — a measured metric the census
# does not name fails, a census line the tree no longer measures fails, and a count that has moved fails. There are
# three kinds of name:
#
#   <kind>-present / -offered / -missing   the four aggregates, and the arithmetic between them is checked
#   sel:<Class>                            how many 10.6 selectors that class answers (one line per shared class)
#   proto:<Name> / fn:<Name>               1 or 0, presence, for every protocol and function 10.6 declares
#   fndecl:<Name>                         1 or 0, whether a header DECLARES it (fn: says whether the library DEFINES it)
#   methods-declared / methods-declared-not-implemented   this tree's OWN declarations, and how many have no body
#   selphantom:<Class>                     how many of that class's own declarations have no body on its chain
#
# **THE PER-CLASS LINES ARE WHAT MAKE MEMBERSHIP PINNED RATHER THAN JUST THE TOTALS.** A census of aggregates alone
# could keep `classes-present 81` while swapping `NSBox` for `NSMatrix`; with a line per shared class, any change to
# which classes are present moves a line name. The missing set is then fully determined — 10.6's offering from the
# manifest, minus the present set the `sel:` lines name — so the 87 absent classes need no lines of their own.
#
# **AND THE MEASURED NUMBERS, RECOMPUTED RATHER THAN EDITED**, so a reader can see the shape without running anything:
#
#     classes    87 of 168   (52%)    81 missing
#     selectors 2870 of 3609  (80%)  739 missing    49 of 86 classes at COMPLETE coverage
#     protocols  23 of  56   (41%)    33 missing
#     functions  86 of  86 (100%)     0 missing    10 of them REFUSE BY NAME, which this count does not distinguish
#                86 declared, 0 declared-not-defined, 0 defined-not-declared
#     methods   3134 declared on this tree's own classes, 4 with NO body on the chain (0.1%)
#
# Three things those five lines say together. The 80% on selectors is the strongest part of the tree and the reason a
# hand count that looked only at filenames undersold it by a factor of two. THE FUNCTIONS ARE FINISHED — 86 of 86, and
# the two disagreement counts are zero — which is why this paragraph no longer calls them the weakest part: it said so
# when `NSRectFill` was absent, and that sentence was exactly the kind of prose this file's header warns about, still
# reading "the tree does not yet fill a rectangle" three slices after it did. And the 50% on classes is the honest
# version of the headline — the desktop CORE is deep, the periphery is empty.
#
# **AND THE SAME QUESTION TURNED ON THIS TREE RATHER THAN ON APPLE: `methods-declared-not-implemented`.** Everything above
# asks what APPLE declares and this tier answers. That metric asks what THIS TIER declares and never implemented — a
# selector named in a header with no body anywhere on the class or its ancestors. It is the method-level twin of the
# function gap, and it is a contradiction rather than a debt: `-respondsToSelector:` would answer NO for a door the
# header promises.
#
# **THE FIRST THREE MEASUREMENTS OF IT WERE ALL WRONG, IN THE SAME DIRECTION, AND THE COLLAPSE IS THE RECORD THAT MAKES
# THIS ONE TRUSTWORTHY: 1,138, then 118, then 47, now 7.** Each error was a blind spot in the reader, not a change in the
# tree, and each is worth naming because each one looked exactly like a finding:
#
#   1,138 -> 118   each declaration was counted on EVERY SUBCLASS as well as where it is written, so one absent body on
#                  `NSResponder` reappeared in twenty descendants. A declaration lives where it is written.
#   118   -> 47    `NSEvent.m` carries forty `@synthesize` lines and the tree writes most of its booleans as MACRO PAIRS
#                  (`FN_FLAG_PAIR(setOneShot, isOneShot, _oneShot)`), so the accessors are compiler-generated and appear in
#                  no method list at all. A declaration the compiler satisfies is satisfied, and the macro's own
#                  definition names the two selectors it expands to.
#   47    -> 7     `@property (getter=isHidden) BOOL hidden` DECLARES `isHidden`, NOT `hidden`. Ignoring the `getter=`
#                  attribute manufactured phantoms on almost every class with a boolean — sixteen on `NSView` alone.
#
# What survives is a number small enough to AUDIT BY HAND, and it has now been audited: the four that remain are ALL
# INFORMAL-PROTOCOL HOOKS declared on `NSObject` so that a subclass may adopt them (`controlTextDidBeginEditing:`,
# `controlTextDidChange:`, `controlTextDidEndEditing:`, `validateToolbarItem:` — the era's protocol-by-category idiom,
# not a promise that `NSObject` implements a page). THE THREE GENUINE GAPS THE PIN EXPOSED ARE FIXED, and they are worth
# naming because the metric is what found them: `NSCell`'s `representedObject` was DECLARED as a property with no
# accessors and no storage behind it (`-setRepresentedObject:` was an unrecognized selector — a crash, not a gap), and
# `NSDraggingItem` had a `setDraggingFrame:` with a getter and no setter. Both are now real, and the count fell from 7 to
# 4 as a deliberate act rather than by drift.
#
# **EACH DECLARATION IS COUNTED ONCE, AT THE CLASS THAT MAKES IT, AGAINST THAT CLASS'S IMPLEMENTED CHAIN.** The first
# one-off measurement of this summed it over every subclass and read 1,138 across 103 classes — an order of magnitude
# too high, because one absence on `NSResponder` becomes twenty in its descendants. A declaration lives where it is
# written, so the census counts it there; the per-class lines (`selphantom:<Class>`) name which fourteen classes carry
# the 118, and the largest are `NSEvent` 39, `NSWindow` 27, `NSView` 16 and `NSCell` 11.
#
# NOTE THE ONE DELIBERATE EXCLUSION. `NSFileWrapper` is declared by 10.6's AppKit (`AppKit/NSFileWrapper.h`) but is
# Foundation's in this tree, so it is attributed to Foundation to avoid charging one class to two ledgers. The
# manifest applies that rule at generation time via its second framework argument; the census never sees it.
